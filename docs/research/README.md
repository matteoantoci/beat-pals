# Beat Pals research

This folder holds the research for Beat Pals. Each topic has one file. Downloaded audio and tool output go to `docs/research/.cache/`, which git ignores.

## Decisions so far

These decisions come from the discussion with the parent.

| # | Decision | Reason |
|---|---|---|
| 1 | The game is a PWA, not a Swift app. | A free install on the Home Screen. A 4-year-old child needs a hit window of about ±250 ms, so web audio latency is not a problem. |
| 2 | The game is private, for one child. | Songs that the family owns are private use. |
| 3 | The hosted code contains no songs. Songs reach the device through a private Wasabi bucket (decision 14). | An iOS PWA needs HTTPS, so the code is on a server. Songs on that server are a publication. |
| 4 | Songs are real recordings, not generated melodies. | Generated melodies sound flat to the child. |
| 5 | The main song source is the family's own audio files of children's songs. The Mac makes a chart from each audio file (decision 11). Clone Hero folders and `.sng` files are a second input, not a requirement. | The family owns many children's songs. The parent does not want to depend on Encore. |
| 6 | The main device is an iPhone 12 with the latest iOS. The layout works in portrait and in landscape, and it also adapts to an iPad. | The child uses this iPhone. iOS cannot lock the orientation of a Home Screen web app, and the Portrait Orientation Lock of the phone can keep it in portrait (see `pile-pals/research/native-feel/shell.md`). In portrait, 3 lanes over the full width of 6.46 cm are 2.15 cm each, above the 2 cm minimum. Portrait also gives a longer note highway: about 13 cm, against about 6 cm in landscape. The latest iOS is later than 18.4, so `.ogg`, `.opus`, and `webkitdirectory` work. |
| 7 | The first prototype uses children's songs from Encore. A first version of `prepare-song` on the Mac unpacks each `.sng`, mixes its audio files with `ffmpeg` into one `.m4a`, and keeps the chart. The local dev server serves the result from `songs/.prepared/`, which git ignores. The prototype has no Beat This and no Wasabi. | These charts exist already, so the prototype can test play before Beat This and the sync exist. The game then decodes one file only, as in the final design. |
| 8 | Lanes that grow with the child: 1, then 2, then 3 lanes, as in P12. Revised on 2026-11-20; the old rule "any lane counts" is gone. | One lane shows the real rule. "Any lane counts" with 3 lanes on screen can teach the child that lanes do not matter. |
| 9 | A hit adds a sound (a clap or a sparkle) and an animation. A miss changes nothing in the music. Later, a miss can make one track 6 dB quieter, if `prepare-song` splits the song with Demucs. | An owned audio file has no separate instrument tracks. No failure for the child. |
| 10 | Rewards are earned stars and record colors only, as in P12. No sticker book for now. | The music is the main reward. Stars and records give information about progress. A collection of prizes can move the motivation from the music to the prize (Lepper, Greene, and Nisbett, 1973). A collection can come later if the child asks for it. |
| 11 | The Mac makes the charts, automatically. The parent does not prepare each song by hand. A watcher on the Mac finds new songs in `songs/`, runs `prepare-song`, and uploads each result to Wasabi (decision 14). | The parent chose the Mac. Beat This in Python is more accurate than a beat detector in the browser. |
| 12 | The song inbox is the folder `songs/` in this project. Git ignores it. The parent copies audio files into it, and the Mac watcher does the rest. | The parent chose it. Owned audio must never go into git. |
| 13 | Each song in the song list shows a picture, as in Spotify. The picture comes from, in this order: a picture file next to the audio in `songs/` with the same name, the artwork in the audio file, the cover of a Clone Hero folder, and an online cover search (any free source, for example the iTunes Search API, Deezer, or the Cover Art Archive). A tap on a song card plays 5 s of the chorus. A second tap or a large play button starts the song. | The child cannot read the titles. Songs from one album share one cover, for example all songs of "Frozen". A sound preview and a picture of the parent's choice tell them apart. |
| 14 | Sync through a private Wasabi bucket. The Mac uploads each prepared song and a `manifest.json` with a write key. The game reads the manifest at start and downloads new songs into IndexedDB. It uses a read-only key that the parent enters one time in the parent area. The key is never in the code. The bucket has a CORS rule for the game's origin and no public access. | The parent already has a Wasabi account. The sync is fully automatic, and the Mac does not have to be on. Wasabi supports bucket CORS (docs.wasabi.com, "Cross-Origin Resource Sharing (CORS)"). A private bucket with keys is not a publication (decision 3). |
| 15 | No special mode for two players. The parent claps or taps along next to the child. | Research shows that a live partner helps the child keep the beat. This needs no code. Turns on one phone can come later. |
| 16 | Solid and HTML for the shell (menus, song list, parent area), as in Pile Pals. PixiJS (WebGL) for the play screen. Each frame places the notes from the audio clock (`getOutputTimestamp()`). | Rich hit effects (sparkles, bounce, flash) at 60 fps. The shell can reuse Pile Pals code. A full game engine is too large and duplicates the shell. |
| 17 | A flat vertical note highway with a small tilt, not a 3D perspective. | Notes stay large over the full screen. In a 3D perspective, far notes are very small on an iPhone. |
| 18 | MVP delivery, decided on 2026-11-22: the songs ship with the app, encrypted. `prepare-song` encrypts each ready song with a random family key (AES-GCM). A `deploy` command on the Mac pushes the app and the encrypted songs to GitHub Pages. The parent enters the key one time in a guided "Songs" setup in the parent area of the Home Screen app. The app then downloads the songs into Cache Storage, one file at a time with progress, and plays offline. This replaces the Mac dev server delivery of P11 and moves the Home Screen install, the service worker, and offline play into the MVP. The plain audio and the song titles stay private; the number of files and their approximate sizes are public. Details: `docs/adr/0001-encrypted-songs-on-a-static-host.md`. | The parent wants the game to play on the iPhone with no Mac. Without the key, the public files are random data, so decision 3 still holds: the song audio is not published. A static host needs no server code, unlike a Cloudflare Worker with a key check. |

## Approved proposals

These proposals come from the research. The parent approved P1 to P8, and P15 on 2026-11-26. They have the same weight as the decisions above.

| # | Proposal | Reason |
|---|---|---|
| P1 | The child chart is simpler than Clone Hero "Easy". The lane count and the note gap come from the current step of P12 (1 to 3 lanes; 700, 625, or 550 ms). (Speed steps replaced by open question 10, 2026-11-22: they are now beat patterns.) The filter thins by the gap. It prefers notes on strong beats. Notes off the beat stay only at the diamond color (P12). Revised on 2026-11-20. | Clone Hero "Easy" is for adult beginners. Each step of P12 changes one thing only, so notes off the beat come last. |
| P2 | Dropped by the parent on 2026-11-20: no beat charts. Every song uses a human chart (P11). Beat charts can come back only by a new decision. | A beat chart could make the game feel boring. |
| P3 | A `prepare-song` script on the Mac makes each song ready. It takes a Clone Hero folder, a `.sng` file, or a bare audio file. It mixes the instrument files with `ffmpeg amix=normalize=0` into one `.m4a` (AAC) file, then runs `loudnorm` to about -14 LUFS, so that every song plays at the same volume. It adds a beat grid from Beat This when the chart has no real tempo map. It adds the picture (decision 13). It writes one small zip, and the watcher uploads it (decision 14). | Beat This is Python and runs on the Mac (decision 11). One `.m4a` file decodes on every iOS version and keeps the memory use of the device to one decoded song. The default `amix` divides each input by the number of inputs, so a song with 8 to 10 parts would play much quieter than a song with one `song.opus`. |
| P4 | Timing for the child: a "good" window of ±250 ms, a "great" window of ±100 ms, a gap of 550 to 750 ms between notes, a hit on `pointerdown`, and no penalty for extra taps. (Speed steps replaced by open question 10, 2026-11-22: single gaps can go down to about 430 ms.) (Changed on 2026-11-26 and 2026-11-27: an extra tap still changes nothing in the play, but some extra taps lower the score for the star. At level 0, a second tap on a hit note and a tap in a rest count. At bronze and up, only a tap in another band lane, inside the good window of a hit note, counts. See the spec, "Play rules".) | 5-year-old children tap with a spread of about 89 to 120 ms. Above a 1 s gap, fewer than half of their taps hit. See `child-rhythm-design.md`. With one lane and free taps, the child tapped all the time with no look at the screen (parent, 2026-11-26). |
| P5 | No fail state. The song never stops. A play below the star score (80% since 2026-11-26) earns no star but takes nothing away (P12). For the miss behavior, see decision 9. | A failure state feels like a punishment to a 4-year-old child. Guitar Hero World Tour "Beginner" and Toca Band use the same approach. |
| P6 | A calibration screen for the parent sets one audio offset in ms, with a tap test or a slider. An early tap schedules its hit sound at the note time (`AudioBufferSourceNode.start(noteTime)`), so it sounds on the beat. A late tap plays its hit sound at once, because the note time is already past; it sounds up to 250 ms late. | AirPods add about 45 to 190 ms. The browser cannot detect AirPods, and `outputLatency` on iOS is not reliable. See `ios-pwa-audio.md`. A sound cannot start in the past, so only early taps can snap to the beat. |
| P7 | Replaced by P12 on 2026-11-20. Soft holds and doubles keep these rules: a soft hold counts when the finger stays down for half of the length, and an early release never counts as a miss; a double uses 2 adjacent lanes and counts when either lane is tapped. | Children hold a tap up to 4.2 s, and two-hand multi-touch succeeds only 54% of the time at age 4 to 5. iOS reports a palm as one touch point, so a palm cannot press 2 lanes. A beat chart has no note lengths, so holds need a sustain from a Clone Hero chart. |
| P8 | Inbox layout. `songs/` is input only. Each audio file at the top level is one song: `.m4a`, `.mp3`, `.flac`, `.wav`, `.aiff`, `.ogg`, `.opus`, or `.sng`. An image with the same name (`.jpg` or `.png`) is its picture. Each subfolder with `notes.chart`, `notes.mid`, or `song.ini` is one Clone Hero song; the files inside it are not separate songs. The watcher skips other subfolders, dot-files, dot-folders, and `.m4p` files, and logs each skip. The output goes to `songs/.prepared/`, which the scan never enters. | The parent wants one folder. The dot keeps the output out of the scan, so the watcher does not read its own output as new songs. A flat scan of a Clone Hero folder would treat each instrument file as a song. Keep the original files: their tags give the picture and the title, and each extra lossy conversion loses quality. |
| P15 | Play sessions: the sunset limit. A session has a time limit in minutes that the parent sets (5 to 30, default 10). A sun at the top of the song list shows the time in 3 stages: day, late afternoon, sunset. The stage changes only when the song list opens. When the list shows the sunset, the next song is the last song: its load scene shows a full-screen sunset with a music-box tune, the song plays to its end, and then the pals say goodbye and fall asleep. The title screen then shows the night with no play button and no title music. When the rest time ends, the night title shows first light, and a tap wakes the pals. The parent sets the sessions per day (1 to 6, default 4). The game spaces the sessions by 12 h divided by the sessions per day, and allows at most that number of session starts in any 24 h, with no clock time and no day boundary. "Open a new session now" in the parent area ends the sleep. Time counts only while the game shows the song list or a play. The play screen does not change. Revised on 2026-11-27 (no clock time). Details: the play-sessions spec. | A stop by the technology upsets a child less than a stop by a parent. The child cannot read a clock, so she must see the end come: the sunset list always means that the next song is the last one, and the limit never cuts a song. The health guidance for ages 2 to 5 is about 1 hour of screen time each day. See `play-time-limits.md`. |

A play with about 70% of the notes hit earns the next star and opens the next speed step; the third star opens the next color. At silver and gold, a pal joins the band. Stars are never lost. A play below 70% earns nothing and takes nothing away; the end of each song shows how well she played with no numbers (more notes hit, more pals dance, more confetti). ## Known facts

- AutoChart.eu gives a zip with `notes.mid`, one audio file for each instrument, `song.ini`, and cover art (source: its guide `add-songs-to-clone-hero`).
- SongHero and chartgen write `notes.chart`. chartgen probably runs on macOS from source, on the CPU only (not tested). See `auto-charting.md`.
- The tempo map of a chart is more important than its notes. SongHero writes one fixed BPM. For such a chart, the game must get the beats from the audio.
- Read `notes.mid` with `midi-file`, not `@tonejs/midi`. `@tonejs/midi` drops markers, SysEx events, and notes on extra MIDI channels. See `chart-formats.md`.
- The development computer is a MacBook Pro M2 with 32 GB. Local ML tools can run on it.
- The sister project `pile-pals` uses Solid, Vite, `vite-plugin-pwa`, and the `playback` audio session.
- Chorus Encore has about 96,700 charts. Each download is one `.sng` file with the chart, Ogg Opus audio, and cover art. How a `.sng` file reaches the game depends on open question 6: through the Mac script, or by a direct import on the device.
- The audio in an Encore `.sng` file is for private family use only, so it is never published in plain form. A later route: take only the chart from Encore, buy the track on the iTunes Store, and let the Mac script align the bought audio with the chart (with the `delay` value, or a cross-correlation against the Encore audio).
- Safari decodes Ogg Vorbis and Ogg Opus only from iOS 18.4. On an older device, the Mac converts the audio to `.m4a` before the import.
- iOS ignores unknown extensions in `accept`. If no extension is known, every file is greyed out. `.sng` is an unknown extension, so a direct `.sng` import must leave `accept` off and check the file type after the selection [UNVERIFIED: test on the device]. `accept="audio/*"` greys out MP3 and M4A files (WebKit bug 242110).
- From iOS 18.4, `webkitdirectory` lets the parent pick an unzipped song folder.
- The Home Screen app has its own storage, without the 7-day deletion of Safari. The parent must import songs inside the installed app, not in a Safari tab.
- Safari draws at 60 Hz in a Home Screen app, also on ProMotion screens. Low Power Mode drops it to 30 fps. Each frame reads the audio clock with `getOutputTimestamp()`.
- Do not play songs through an `<audio>` element. WebKit has open bugs where its time drifts from the audio. Use a decoded `AudioBuffer`.
- Apple Music songs are copy-protected and the game cannot use them. iTunes Store purchases have no copy protection.

## Open questions to discuss

1. ~~iPhone or iPad?~~ Answered: decision 6.
2. ~~Which songs does the child love?~~ Answered: decisions 5 and 7.
3. ~~Input: tap the lane, or tap anywhere on the beat?~~ Answered: decision 8. Later difficulty: P7.
4. ~~What happens on a missed note?~~ Answered: decision 9.
5. ~~Rewards: stars, stickers as in Pile Pals, or none?~~ Answered: decision 10.
6. ~~Must the Mac process each new song?~~ Answered: decision 11.
6a. ~~Where are the songs on the Mac?~~ Answered: decision 12.
6b. ~~How do new songs reach the iPhone?~~ Answered: decision 14.
7. ~~Do you want a mode for two players?~~ Answered: decision 15.
8. ~~Do the proposals P1 to P8 become decisions?~~ Answered: yes, all of them.
9. ~~Can a double use lane 1 and lane 3?~~ Answered on 2026-11-22: no, a double uses 2 adjacent lanes only (P7, carried by P12). From platinum up, a chart chord on lanes 1 and 3 becomes a 1 + 2 double: the game keeps the lane of the lower fret and adds the middle lane. At bronze, silver, and gold, a chord becomes one hit. The 1 + 3 drawing in the style A prototype is not used. Reason: lanes with a gap between them ask for two hands, and two-hand multi-touch succeeds only 53.7% of the time at age 4 to 5 (Vatavu 2015). The arch over the middle lane also breaks rule C5 in `game-ui.md`.
10. ~~The 700, 625, and 550 ms speed steps give the same chart for most songs. Change them?~~ Answered on 2026-11-22: yes. Two reviews ran the child filter on the 31 songs. Notes on the beat are at least one beat apart, so in 22 of 31 songs all 3 steps gave the same chart, and 14 songs had a median gap above 1 s. The speed steps are now beat patterns: step 0 keeps beats 1 and 3 of each bar, step 1 keeps 3 of 4 beats, and step 2 keeps every beat. Above about 140 BPM, half notes count as beats. Single gaps can go down to about 430 ms, below the 550 ms of P4; the parent accepted this. This replaces the ms steps of P1 and P12.
11. ~~Long rests in the lead guitar chart?~~ Answered on 2026-11-22: when the guitar rests for more than about 8 s, the child chart fills the rest with notes from another human chart in the same file: bass, then keys, then drums. Some songs have guitar rests of more than 30 s.
12. ~~Public or private repository?~~ Answered on 2026-11-23: one public repository. It holds the source and, on an orphan `gh-pages` branch, the built site. `deploy` force-pushes that branch as one commit. The song list, the song notes, and the prototypes stay in `.scratch/`, which git ignores. No file in git names a song. This replaces the answer of 2026-11-22 (a private source repository and a public site repository): the parent does not want 2 repositories.
